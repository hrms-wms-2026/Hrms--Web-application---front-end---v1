# Connect Desktop Agent (Settings → Devices) — Design

## Problem

The ONEVO WorkPulse desktop TrayApp's "Connect OneXso Workspace" screen requires an
8-character activation code, generated by `POST /api/v1/monitoring/activation/generate`
on the backend (self-service, tied to the calling employee's own account, rate-limited
to 3 codes/hour, each code expires after 600 seconds). No frontend page currently calls
this endpoint — users have no way to obtain a code without a developer hitting the API
directly.

## Scope

MVP only: a single "generate my own activation code" card. Explicitly out of scope for
this pass:
- Listing or revoking connected devices (no backend list-devices endpoint exists yet —
  `MonitoringActivationController` only exposes `generate` / `exchange` / `refresh` /
  `revoke`(self, via bearer token). Adding a list endpoint is a separate backend + frontend
  effort.
- Admin generating a code on behalf of another employee — the backend handler resolves
  the code to `ICurrentUser`, there is no such capability server-side.

## Location & access control

- New route `settings/devices`, added as a sibling of `settings/clock-in-policy` in
  `src/app/app.routes.ts`, lazy-loaded standalone component.
  - `canActivate: [permissionGuard]`
  - `data: { title: 'Devices', modules: ['desktop_agent_gateway'] }` — no `permissions` entry:
    `MonitoringActivationController.Generate` requires only `TenantPolicy` (any authenticated
    employee), no specific permission code. `settings:device` was considered and rejected here —
    it's `PermissionSeeder.cs:166`'s "view biometric device connection status" permission
    (fingerprint/biometric hardware), unrelated to the desktop tray agent.
- New nav entry in `src/app/layouts/main-layout/nav/nav-items.config.ts`:
  - `id: 'settings-devices'`, `label: 'Devices'`, `path: '/settings/devices'`,
    `requiredModules: ['desktop_agent_gateway']`, no `requiredPermissions`

The module gate mirrors the existing `clock-in-policy` entry's pattern; the permission gate is
intentionally omitted per above.

## Component

`src/app/modules/settings/feature/connect-device/connect-device.component.ts`
(standalone Angular component, own `.html`/`.scss`, following the existing
`clock-in-policy-form` component's file layout).

Behavior:
- Idle state: short explainer text + "Generate Code" button.
- Loading state: button shows a spinner while the request is in flight.
- Success state: renders the 8-character code in a large monospace box, a
  copy-to-clipboard icon button next to it, and a live countdown (`mm:ss`) initialized
  from the response's `expires_in_seconds` (600). Countdown ticks client-side via
  `setInterval`/`timer` — no polling of the backend.
- Expired state: once the countdown reaches 0, the code box clears and shows
  "Code expired — Generate a new one" with the button re-enabled.
- Explanatory copy under the code, matching the TrayApp's own wording: "Paste this code
  into the OneXso Workspace desktop app within 10 minutes."

## Data access

`src/app/modules/settings/data-access/activation-api.service.ts`:

```ts
@Injectable({ providedIn: 'root' })
export class ActivationApiService {
  private readonly http = inject(HttpClient);

  generate(): Observable<ActivationCodeResponse> {
    return this.http.post<ActivationCodeResponse>(`${environment.apiUrl}/monitoring/activation/generate`, {});
  }
}
```

`ActivationCodeResponse` model: `{ code: string; expires_in_seconds: number }`
(matches backend `ActivationCodeResponseDto`, snake_case field names as returned by the API).

CSRF: no new handling needed — the existing `csrf.interceptor.ts` already attaches
`X-CSRF-Token` to mutating requests globally.

## Error handling

- `429` (rate limit exceeded, >3 codes/hour): inline message "Too many codes requested.
  Try again in a bit." Button stays enabled so the user can retry once the window rolls over.
- `401`: no special handling needed — the existing global auth interceptor already
  redirects to login on 401.
- Network / `5xx`: generic inline error message with a "Retry" affordance on the same button.

## Testing

- `connect-device.component.spec.ts`: click Generate → service called → code + countdown
  rendered; countdown reaching 0 clears the code and re-shows the button; 429 response
  renders the rate-limit message.
- Route/nav gating spec mirroring `clock-in-policy.routes.spec.ts` and the relevant case
  in `nav-access.spec.ts`, asserting the `settings:device` permission and
  `desktop_agent_gateway` module gate on both the route and the nav entry.
